# 安全設計

## 基本原則

zconfig は「エージェントの提案」と「人間が許可したファイル変更」の間に、機械的な境界を置きます。

1. 外部エージェントの出力を信頼せず、構造と変更範囲を検証する
2. 人間の最終確認を必須にし、自動反映しない
3. 機密値を既定で表示・共有・保存しない
4. 元ファイルと最終変更集合をダイジェストで結び付ける
5. 検証不能を成功として扱わない

## 現在実装されている防御

- 厳格な RFC 8259 JSON、重複キー拒否、SHA-256 による元ファイル照合
- JSON Pointer、変更 ID、親子関係を含む対象競合の検証
- コメント対象外を含むエージェント修正の全体拒否
- シェルを介さない実行ファイル＋引数配列での起動
- タイムアウト、キャンセル、標準出力／標準エラーのサイズ制限
- 未知フィールド、余分な出力、要求 ID 不一致の拒否
- スキーマ注釈と保守的な名前判定による機密候補の既定マスク

## 機密値の方針

スキーマの `x-zconfig-sensitive`、または正規化した設定名からパスワード、トークン、秘密鍵などの候補を分類します。候補は誤検知の可能性を示しつつ、安全側で伏せます。

値の一時表示とエージェントへの共有は別の権限です。どちらも項目とセッション指紋へ結び付けた明示確認と短い有効期間を持ち、共有権限は一回の呼び出しで消費されます。conceal、セッション終了、再開ではメモリ上の権限を破棄します。共有した既知の値は、エージェントの stdout、stderr、エラー、候補結果から表示・保存前に完全一致で再マスクします。

## セッションと監査

計画ではレビュー状態をプロジェクトローカルへ保存しますが、生の値、コメント本文、プロセス出力、最終確認、一時的な機密権限は保存しません。

監査ログは `.zconfig/audit/<session-id>.jsonl` に、値を含まないイベントとして追記します。連番とダイジェスト鎖で欠落や改変を検出し、重要操作で追記に失敗した場合は操作自体を止めます。結果コードも契約で許可した安定コード形式に限定し、自由文を保存しません。

## 安全なファイル反映

実装した反映手順は次の通りです。

1. 元ファイルを再度開き、通常ファイルであることと SHA-256 を検証
2. 承認済み変更だけから最終内容を再構成
3. 同一ディレクトリの一時ファイルへ書き込み、flush と権限を確認
4. 変更対象外のバイトが元ファイルと一致することを検証
5. 人間が確認した最終集合とダイジェストが一致する場合だけ置換
6. 途中失敗時は元ファイルを維持し、必要なら復旧記録を残す

分離したコア起動間の短命な最終確認には、0600 の値を含まない `.zconfig/runtime/` capability 記録を使います。反映要求は提案・判断・コメント状態・外部検査結果を再送し、コアが最終集合とダイジェストを再計算した後にだけ capability を一回消費します。

## 外部バリデーター

外部バリデーターはシェルを介さず、登録済みの実行ファイルと引数で起動します。候補は元ファイルと同じディレクトリの一時ファイルとして渡し、タイムアウト、非0終了、過大出力、不正JSON、候補ダイジェスト不一致、明示的な失敗をすべて反映の阻害要因として扱います。stdout と stderr は既知の共有値を再マスクしてから診断へ変換します。未登録のバリデーターは成功ではなく `unverified` です。

## 制限値

| 対象 | 上限・既定値 |
|---|---:|
| 元 JSON | 10 MiB |
| JSON ノード | 100,000 |
| 変更項目 | 1,000 |
| 修正回数 | 10 |
| 監査イベント | 5,000 |
| プロトコルメッセージ／診断ストリーム | 16 MiB |
| Zig コアの既定タイムアウト | 10 秒 |
| エージェントの既定タイムアウト | 120 秒 |
| バリデーターの既定タイムアウト | 10 秒 |

## 脅威モデル上の対象外

zconfig は、実行中ユーザー自身や OS 管理者から秘密を守るサンドボックスではありません。登録した実行ファイルに明示共有したデータの利用も制御できません。信頼できる実体だけを、最小限の環境変数と作業ディレクトリで実行してください。
