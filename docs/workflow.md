# レビューワークフロー

## 用語

zconfig では、一つの設定変更を **変更項目** と呼びます。変更項目には、安定した ID、JSON Pointer 形式のパス、操作種別、現在値、提案値、理由、検査結果が含まれます。

自然言語コメントは変更項目に紐づきます。ファイル全体に曖昧な指示を出すのではなく、「この項目をどう直してほしいか」を人間が表現するためのものです。

## 想定する流れ

### 1. 外部エージェントが変更案を作る

変更案は zconfig の JSON 契約に従い、元ファイルの SHA-256 ダイジェストを含めます。変更案の作成後に元ファイルが変化していた場合はレビューを開始せず、古い提案を誤って適用しません。

変更操作は `add`、`replace`、`remove` です。変更先は RFC 6901 JSON Pointer で指定します。詳細な形式は [proposal.schema.json](../specs/001-review-config-changes/contracts/proposal.schema.json) が正本です。

### 2. 人間が変更項目を確認する

TUI は各項目について、設定パス、操作種別、現在値と提案値、変更理由、検査結果、レビュー状態を提示します。機密値は既定で伏せます。

現在の読み取り専用画面では、`j` / `k` または矢印キーで移動し、`Enter` で詳細、`d` でソース差分、`/` で絞り込み、`?` でヘルプ、`q` で終了できます。承認・コメント操作の最終キーバインドは実装時に確定します。

### 3. 必要な項目に自然言語コメントを付ける

例:

```text
背景色とのコントラストが弱いので、もう一段暗い値にしてください。
```

コメントは作成、編集、撤回が可能です。エージェントが修正済みと主張しても自動的には解決せず、人間が確認して初めて解決済みになります。

### 4. コメント対象だけを再提案させる

zconfig は登録済みエージェントへ、コメント対象の変更項目 ID だけを許可範囲として渡します。

- 対象外の項目を変更した応答は、修正全体を拒否
- ID、パス、元ファイルのダイジェストなどの不変情報を変えた応答も拒否
- 受理された場合、実際に変化した項目だけを未決定へ戻す
- 変化しなかった項目の承認・却下は保持

自然言語の解釈をエージェントに任せても、変更範囲そのものは機械的に制限します。

### 5. 採否と最終差分を確認する

この段階は設計済み・未実装です。未決定項目や未解決コメントが残っている場合は反映へ進めません。人間は承認した項目だけから組み立てられた最終差分を別画面で確認し、さらに明示的な最終確認を行います。

### 6. 元ファイルへ安全に反映する

この段階も設計済み・未実装です。反映直前に元ファイルを再読込・再検証し、同じディレクトリの一時ファイルへ構成してから置換します。変更対象外のバイト列はそのまま保ち、失敗時には復旧に必要な情報を残します。

## 状態が無効になる条件

- 元ファイルの内容が変わった
- エージェントの再提案で項目の内容が変わった
- セッションを終了または再開した（最終確認や機密値の一時権限は失効）
- 検査対象や最終変更集合が変わった

## 対象外

- 人間の確認を飛ばす完全自動適用
- 複数人による遠隔レビュー
- 一つのレビューで複数ファイルを同時に変更すること
- JSONC、TOML、YAML の編集（将来候補）
