# アーキテクチャ

## 設計方針

安全性に関わる判断をオフラインで再利用可能な Zig コアへ集約し、人間向けの操作と外部プロセスの調停を Go に分離します。UI やエージェントを交換しても、入力検証と変更範囲の規則が変わらない構成を目指します。

| 構成要素 | 主な責務 | 信頼境界 |
|---|---|---|
| `zconfig-core`（Zig） | JSON 解析、ダイジェスト、JSON Pointer、提案／修正の検証、機密分類、将来の安全な反映 | 安全規則の正本 |
| `zconfig`（Go） | Bubble Tea TUI、レビュー状態、各外部プロセスの起動、将来のセッションと監査 | 値を必要以上に保持しない調停層 |
| 外部エージェント | 最初の変更案と、コメントを受けた限定修正の生成 | 信頼せず、全応答を検証 |
| 外部バリデーター | 任意のプロジェクト固有検査 | 結果をダイジェストへ結び付けて検証 |

## データフロー

```text
                    標準 JSON / 任意スキーマ
                              │
                              ▼
外部エージェント ──提案──▶ Go TUI ──JSON要求──▶ Zig コア
       ▲                      │                     │
       │ コメント対象のみ     │◀──検証済み結果──────┘
       └────再提案要求────────┘
                              │
                        人間の採否・最終確認
                              │
                              ▼
                   安全なファイル反映（未実装）
```

コアと外部コマンドは常駐サービスではありません。一回の起動につき、標準入力から JSON リクエストを一件読み、標準出力へ JSON レスポンスを一件返します。

## プロトコル

プロトコル v1 は、厳格なエンベロープ、起動前の能力確認、安定したエラー分類、型を保った伏せ字を定義します。未知・重複フィールド、過大な入出力、要求 ID の不一致を拒否し、Zig と Go は同じゴールデン JSON で互換性を検査します。正本は [protocol.md](../specs/001-review-config-changes/contracts/protocol.md) と同ディレクトリの JSON Schema です。

## ファイル解析と変更

標準 JSON の意味的な解析に加え、元ファイル上の値のバイト範囲を索引化します。将来の反映処理では変更項目に対応する範囲だけを置き換え、空白、改行コード、数値表記、エスケープなど、無関係な表現を維持します。

RFC 8259 違反、重複キー、通常ファイル以外、規模上限超過、提案の `source_digest` と現在の SHA-256 の不一致は拒否します。

## スキーマ検査

JSON Schema は任意です。対応する共通サブセットのみを決定的に評価し、入力に関係する未対応キーワードがあれば `unverified` にします。独自注釈 `x-zconfig-sensitive` は機密値の分類に使用します。

## ディレクトリ構成

```text
core/                                  Zig の安全コアと単体テスト
tui/cmd/zconfig/                       Go CLI のエントリーポイント
tui/internal/                          TUI、状態、プロトコル、実行器、設定
tests/contract/                        Zig / Go 共通の契約フィクスチャ
tests/integration/                     プロセス境界を含む統合テスト
specs/001-review-config-changes/       仕様、計画、契約、タスク
docs/                                  利用者・開発者向け日本語文書
```

## 最終確認 capability

`assemble_final` と `apply_final` は別々の一回起動プロセスです。短命な確認 nonce は、値を含まない capability 記録として `.zconfig/runtime/` に保存します。反映時には提案、判断、コメント状態、外部検査結果を再送し、コアが最終集合を再計算します。source digest と final-change digest が記録と一致する場合だけ一回使用でき、期限切れ、セッション再開、内容変更では失効します。
